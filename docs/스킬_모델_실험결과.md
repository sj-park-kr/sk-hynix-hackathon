# 스킬·AGENTS.md·서브에이전트 가이드 (실험 검증 포함)

> 2026-10-27, 로컬 Codex CLI 0.164.0으로 실측했습니다.
> - **1차:** Terra 5.6, 조건당 1회 (무료 플랜 시절)
> - **2차:** **Sol 6.1(`gpt-6.1-sol`, medium)**, 과제 3종 × 조건별 3회, 총 42회
>
> 모든 실행이 정답·동작 확인을 통과했으므로, 아래 비교는 "같은 결과를 얼마나 싸고 빠르게 냈나"입니다. 표의 수치는 중앙값(최소~최대)입니다.

## 결론

1. **AGENTS.md는 [`AGENTS.template.md`](AGENTS.template.md)(v2)를 쓰세요.** 실험으로 고친 버전입니다.
   - 모호한 과제에서 코드량은 54% 줄었고(213줄 → 98줄), 새로 읽는 양(비캐시 입력)도 절반 이하로 줄었습니다.
   - 서버를 `0.0.0.0`에 명시적으로 바인딩한 비율이 3/3이었습니다.
2. **"메인은 지휘만" 방식은 비추천합니다.** 독립 기능 3개를 서브에이전트 3개로 병렬 처리하는, 이 방식에 가장 유리한 과제에서도 결과가 나빴습니다.
   - 직접 처리보다 **느렸습니다** (104~114초 vs 80~85초).
   - 토큰은 **4.5~6.5배** 들었습니다.
3. **스킬은 ponytail만 쓰되, 상시 적용이 아니라 리뷰용으로 쓰세요.**
   - ponytail을 상시 적용하면 3회 중 2회가 서버를 `127.0.0.1`에 바인딩했습니다. **시험 미리보기에서 접속되지 않는 설정입니다.**
   - caveman, eli5, humanizer는 쓰지 않는 편이 낫습니다.
4. **설치 요청에는 "스킬"이라는 단어를 넣으세요.** "포니테일 설치해줘"는 공식 플러그인 목록만 찾다가 멈췄습니다. 반면 "포니테일 **스킬** 설치해줘"는 웹 검색으로 저장소를 찾아 설치했습니다. 검색 결과에 이름이 같은 다른 저장소가 섞여 나오므로, 가장 확실한 방법은 `DietrichGebert/ponytail`까지 말하는 것입니다.
5. **이해도 퀴즈는 질문 유형을 지정해야 합니다.** Terra와 Sol 모두에서 확인했습니다.

| **humanizer** | ✕ | SKILL.md가 32.7KB로 무겁습니다. AI로 쓴 문서는 불이익이 없고, 다시 쓰는 과정에서 기술적 사실이 바뀔 위험이 있습니다. |

### ponytail 설치 (git clone 필요 없음)

**방법 1. 터미널에서 직접 입력 (토큰 0)**
```bash
codex plugin marketplace add DietrichGebert/ponytail
codex plugin add ponytail@ponytail
```
그다음 `codex`를 실행해 `/hooks`에서 훅 2개를 신뢰하고, 새 스레드를 시작합니다.

**방법 2. Codex에게 말로 요청 (스킬로 설치, 훅 없음) — 권장**
```
DietrichGebert/ponytail의 ponytail-review 스킬 설치해줘
```
- 저장소 `skills/`에는 스킬이 6개 있습니다(ponytail, -review, -audit, -debt, -gain, -help). 설치 스크립트는 **지정한 경로만** 설치하므로, "포니테일 스킬 설치해줘"라고 하면 메인 `ponytail` 하나만 설치됩니다. 여러 개를 한 번에 설치할 수도 있습니다(`--path skills/a skills/b`).
- **시험에는 `ponytail-review`만 권장합니다.** 메인 `ponytail`은 설명에 "모든 코딩 작업에 사용(Use on any coding task)"이라고 되어 있어서 사실상 상시 적용처럼 자동으로 불려옵니다. 그러면 AGENTS.md 규칙과 겹치고, 상시 적용 실험에서 나온 `127.0.0.1` 바인딩 위험도 따라옵니다.
- 설치 스크립트가 Python을 쓰기 때문에, Python이 없으면 Codex가 `uv run --python 3.12`로 우회했습니다.
- 설치 위치(`~/.codex/skills`)는 작업 공간 밖이라 승인 요청이 뜹니다.

- 플러그인으로 설치하면 **ponytail 규칙이 매 세션 자동으로 켜집니다.** 그러니 AGENTS.md의 `0.0.0.0` 규칙을 꼭 함께 두세요. 템플릿 v2에는 이미 들어 있습니다. 다만 둘을 함께 켠 조합은 실험하지 않았습니다.
- 리뷰 스킬만 원하면 `$skill-installer https://github.com/DietrichGebert/ponytail/tree/main/skills/ponytail-review 설치해줘`라고 하면 됩니다. 이 방법은 실제 설치까지 해 보지는 않았으니 사전 체험 때 확인하세요. 설치 위치는 `~/.codex/skills`입니다.

## 2. AGENTS.md

- 파일: [`AGENTS.template.md`](AGENTS.template.md). 작업 공간 루트에 **`AGENTS.md`**라는 이름으로 만드세요. 개인 PC 파일은 업로드할 수 없으니 직접 타이핑해야 합니다.
- **AGENTS.md도 서술형 질문 대상이 될 수 있습니다.** 1차 퀴즈 실험에서 모델이 커밋 기록의 AGENTS.md 변경을 짚어 질문했습니다. 규칙마다 왜 넣었는지 설명할 수 있어야 합니다.

### v1 → v2에서 고친 점 (2차 실험에서 발견)

| v1의 문제 | v2 수정 | 효과 (Sol, T1 / T2 읽은 출력) |
|---|---|---|
| 에이전트가 `rg -n '.' SPEC.md`처럼 모든 줄에 매칭되는 패턴으로 "rg로 찾기" 규칙을 우회해 파일 전체를 출력 | "**필요한 부분만** 읽는다 … 파일 전체 출력(cat, Get-Content, rg '.') 금지" | 27K → **16K** / 51K → **18K** |
| "요청·README·**명세**에 있는 것만"이 범위를 확인하려고 명세 전체를 읽게 만듦 | "요청받은 것만 만든다" | SPEC을 끝까지 읽은 비율 3/3 → **0/3** (T1) |
| `0.0.0.0` 규칙의 문구가 애매함 | "0.0.0.0(또는 호스트 생략) … localhost·127.0.0.1 바인딩 금지" | `0.0.0.0` 명시 3/3 |

### 알아둘 점
- **커밋:** 로컬 샌드박스에서는 `.git` 쓰기가 막혀 커밋 시도가 모두 실패했습니다(`index.lock: Permission denied`). 사전 체험 때 Codex가 커밋할 수 있는지 확인하세요. 막혀 있다면 이 줄을 "커밋은 내가 직접 한다"로 바꾸고 직접 커밋하세요. git log는 평가 기록으로 수집됩니다.
- **기록 규칙에는 비용이 있습니다.** v2는 4줄 규칙(B4)보다 총 토큰이 약 1.9배입니다(T1 187K vs 99K). 커밋 시도, DECISIONS.md 작성, 테스트, 서버 동작 확인 때문입니다. 새로 읽는 양은 B4와 비슷합니다. 대신 B4는 모호한 과제에서 **3회 중 2회 테스트를 아예 쓰지 않았고** 기록도 남기지 않았습니다. 시험은 git log, 테스트 결과, 판단 근거 문서를 평가하므로 v2를 권장합니다.
- **웹 과제에서는 Codex가 내장 `sites` 스킬(약 12.5K자)을 자동으로 불러왔습니다** (T2 15회 중 12회). 시험 환경에 어떤 내장 스킬이 있는지는 알 수 없습니다.

## 3. 서브에이전트 모델 선정

### 시험 모델 ID (`/model`로 확인하세요)

| 시험 표기 | 모델 ID | 성격 |
|---|---|---|
| Sol 6.1 | `gpt-6.1-sol` | Astra에 가까운 성능. **메인** |
| Sol 6.0 | `gpt-6-sol` | 이전 Sol |
| Terra 5.6 | `gpt-5.6-terra` | 이전 세대 균형형 |
| Luna 6 | `gpt-6-luna` | 빠르고 저렴. 추출·요약·좁은 범위 코딩 |
| ~~Astra~~ | `gpt-6-astra` | **시험에서 사용 금지** |

### 작업별 배정

| 작업 | 누가 | 모델·effort |
|---|---|---|
| 계획, 핵심 구현, 디버깅, 검증, 제출 문서 | **메인이 직접** | Sol 6.1 · medium (어려운 버그만 high) |
| 큰 문서·로그·코드베이스 탐색 후 요약 (읽기 전용) | 서브 (explorer) | Luna 6 · low~medium |
| 오래 걸리는 독립 작업 (각각 수십 분 규모) | 서브 (worker) | Sol 6.1 |
| 제출 전 diff 리뷰 | 서브 또는 `$ponytail-review` | Sol 6.1 |

### 요청 예시
```
gpt-6-luna로 explorer 서브에이전트를 띄워서 src 전체에서 인증 흐름을 찾아 파일:줄 목록과 5줄 요약만 돌려줘. 파일 수정 금지.
gpt-6.1-sol로 서브에이전트를 띄워 git diff를 리뷰해줘. 버그와 누락된 요구사항만 보고하고 수정은 하지 마.
```
- **모델 이름을 항상 명시하세요.** 이름을 생략하면 부모 모델을 따라갑니다. "제일 좋은 모델로" 같은 표현은 Astra가 선택될 위험이 있습니다. 실험에서는 Sol 메인 아래에 자연어로 지정한 `gpt-6-luna`가 4/4 실제로 적용됐습니다(1차 1회 + 2차 3회, 세션 기록으로 확인).
- **서브에이전트의 승인 요청은 그 스레드를 열어야 응답할 수 있습니다.** 출처 라벨이 붙은 요청이 보이면 `o`를 누르세요(공식 문서). 놓치면 작업이 멈춘 채로 기다립니다.

### "메인은 지휘만"을 공정하게 다시 검증 (T3: 서로 다른 파일의 독립 기능 3개, Sol 메인)

| 조건 | 정답 | 시간 | 총 입력 | 비캐시 입력 | 턴 | 서브 동시 실행 |
|---|---|---|---|---|---|---|
| 템플릿, 직접 (TPL) | 3/3 | **80초** (76~99) | **213K** | 19K | 8 | - |
| 템플릿 v2, 직접 (TPL2) | 3/3 | 85초 (84~109) | 226K | 23K | 7~10 | - |
| 지휘 + Luna 3개 병렬 | 3/3 | 114초 (113~164) | 1,390K (**6.5배**) | 146K | 15~27 | 3 |
| 지휘 + Sol 3개 병렬 | 3/3 | 104초 (94~131) | 952K (**4.5배**) | 86K | 18~22 | 3 |

- 서브에이전트 3개가 실제로 동시에 돌았는데도 더 느렸습니다. 서브에이전트를 띄우고, 각자 맥락을 다시 읽고, 메인이 결과를 다시 검증하는 비용이 병렬로 얻는 이득보다 컸습니다.
- **Luna는 토큰당 단가는 싸지만 Sol보다 토큰을 46% 더 썼습니다.** 시험은 토큰 사용량을 추적하므로 Luna로 바꿔도 이득이 없습니다.
- 기능 하나가 수십 분씩 걸리는 큰 과제라면 병렬화가 유리할 수 있습니다. 이번 실험의 기능은 각각 1분 안팎이었습니다.
- 서브에이전트가 확실히 이기는 경우는 **메인 컨텍스트를 가볍게 유지할 때**입니다(1차 실험에서 71K vs 195K). 3시간 동안 쌓이는 탐색·로그 같은 잡음만 넘기세요.

## 4. 실험 상세 (2차, Sol 6.1 · medium · 조건별 3회)

**조건**
- A: AGENTS.md 없음
- B4: 4줄 규칙 (오버엔지니어링 금지, 필요한 부분만 읽기, 필요한 줄만 수정, 짧은 답변)
- PT: ponytail AGENTS.md (상시 적용)
- TPL: 템플릿 v1
- TPL2: 템플릿 v2

### T1. 명세가 명확한 과제 (23.7KB SPEC 중 8절만 관련, 숨김 테스트 7개)

| 조건 | 시간 | 총 입력 | 비캐시 | 출력 | 읽은 출력 | SPEC 끝까지 | src 줄 | test 줄 |
|---|---|---|---|---|---|---|---|---|
| A | 58초 | 172K | 27K | 1,989 | 24K | 0/3 | 9 | 60 |
| B4 | **42초** | **99K** | **14K** | 1,504 | **11K** | 0/3 | 8 | 50 |
| PT | 57초 | 177K | 29K | 1,858 | 32K | 0/3 | 6 | 52 |
| TPL | 54초 | 171K | 30K | 1,739 | 27K | 3/3 | 9 | 48 |

## 5. 이해도 퀴즈 프롬프트

### 권장 프롬프트 (과제 시간에 Codex에게)
```
이 프로젝트를 내가 제대로 이해했는지 점검하고 싶어. 코드, git log, 문서를 근거로 주관식 퀴즈 8개를 한 문제씩 내줘.
유형을 섞어줘: 왜 이렇게 설계했나 / 다른 방법 대비 장단점 / 어떻게 검증했나 /
특정 입력에서 코드가 어떻게 동작하나 / 남은 한계 / 전제가 틀린 질문 1개.
내가 답하면 틀린 사실만 짧게 짚어줘.
```

### 비교 실험 (같은 작업 결과를 대상으로, 읽기 전용)

| 프롬프트 | Terra (1회) | Sol (2회) |
|---|---|---|
| Q1 "심사관이 낼 후속 질문 8개" | 평가자 관점, 깊이 있음 | 설계·검증·엣지 케이스 위주로 깊이 있음. **전제가 틀린 질문은 0개** |
| Q2 "이해도 퀴즈 8개" (유형 미지정) | **8개 모두 암기형** | 7개 정도가 "무엇을 반환하나 / 어떻게 동작하나". **"왜"·대안 비교·전제 오류 질문은 0개** |
| Q3 권장 프롬프트 (유형 지정) | 모든 유형 + 전제 오류 1개 | 2회 모두 설계 이유, 대안 비교, 입력 추적, 검증 빈틈, 한계, 전제 오류(실제로 없는 CLI 옵션)가 고르게 나옴 |

→ 퀴즈 형식으로 물어도 되지만, **유형 지정은 빼면 안 됩니다.** 한 번에 약 50K 입력 토큰이 듭니다(Terra 측정 기준).
