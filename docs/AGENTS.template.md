# 작업 규칙

## 범위
- 요청받은 것만 만든다. 추상화·옵션·설정·"나중을 위한" 코드 금지.
- 수정은 필요한 줄만. 관련 없는 리팩터링·포맷 변경 금지.

## 읽기
- 필요한 부분만 읽는다: rg로 키워드 위치를 찾고 그 줄 범위만 출력한다. 파일 전체 출력(cat, Get-Content, rg '.') 금지.

## 문서 안내
<!-- 당일 과제의 README·docs/를 보고 경로를 채운다. 없는 줄은 지운다 -->
작업 전에 아래에서 해당하는 문서만 열어 필요한 부분을 읽는다. 문서와 요청이 다르면 추측하지 말고 묻는다.
- 무엇을 만들지, 필수 요구사항, 제출 파일명 → `README.md`, `docs/____.md`
- 코드 구조, 파일을 어디에 둘지 → `docs/____.md`
- 이미 정한 결정과 그 이유 / 새 결정 기록 → `docs/____.md`
- 범위 밖이라 나중으로 미룬 것 → `docs/____.md`
- 제공 데이터 형식 → `____/` (전체 출력 말고 앞 몇 줄만)

## 실행·검증
- 서버는 0.0.0.0(또는 호스트 생략)으로 열고 포트를 알려준다. localhost·127.0.0.1 바인딩 금지.
- 바꾼 뒤 관련 테스트를 실행해 결과를 보고한다. 새 분기·파서 로직에는 작은 테스트 1개.
- 기능 단위로 git commit한다. 메시지는 한국어로 쓰고 '왜'를 넣는다(코드 식별자는 원문 그대로). push 금지.

## 기록
- 중요한 결정은 DECISIONS.md(과제가 지정한 문서가 있으면 그 문서)에 한 줄: 결정 / 이유 / 버린 대안 / 검증.
- 요구사항이 모호하면 추측하지 말고 질문 목록으로 돌려준다.

## 답변
- 결론 먼저, 3줄 이내. 인사·계획 예고·요약 반복 금지. 코드·명령·경로·오류는 그대로.
- 마지막 줄: 확인 못 한 것과 위험.
- 내가 설명·목록·퀴즈를 요청하면 길이 제한 없음.

## 서브에이전트
- 기본은 직접 작업한다. 서브에이전트는 내가 요청할 때만, 모델을 명시해서 띄운다.
