# SK하이닉스 AI 해커톤 2026 — 2차 예선 대비 (Cofa Probe 데모 시험)

2차 예선 플랫폼인 **크래프톤 Cofa Probe**의 응시 환경을 로컬(VS Code + 터미널 Claude Code)에서 재현한 데모 시험입니다.
시나리오의 회사·인물·수치는 모두 가상입니다.

## 2차 예선 정리

| 항목 | 내용 |
|---|---|
| 일정 | 2026-10-31(토) 10:00~14:00. 9:40부터 사전 준비, **모든 절차가 14:00에 종료** |
| 준비물 | 웹캠 PC(**듀얼 모니터 불가**), 카메라가 되는 스마트폰, 신분증, 혼자 있는 공간 |
| 평가 내용(공식) | AI를 활용한 실무형 과제의 **수행 과정**과 **결과물**, 본인이 수행한 과정·결과물에 대한 **이해도** |
| 추가 안내 | 10/26 1차 안내, 10/29 최종 안내와 응시 링크(info@cofa.krafton.ai) |
| 화면 | 브라우저 웹 IDE: 탐색기·에디터, 아래 bash 터미널(AI CLI), 오른쪽 **실무자 시나리오 에이전트 채팅**, 상단 타이머·카메라 |
| 워크스페이스 | `README.md`, `AGENTS.md`, `.mcp.json`, `.env.example`, `docs/`(PRD·ARCHITECTURE·DECISIONS·ROADMAP), `uploads/`, `src/`, git |
| 실무자 | 요구사항을 한 번에 알려주지 않음. 제대로 물어야 숨은 조건이 나옴 |
| 수집·채점 | 코드·커밋·프롬프트·도구 설정·AI 대화·실무자 대화·실행 기록. 여러 AI 채점 에이전트가 소스코드와 실행 결과까지 보고 항목별 판정문과 증거 위치를 남김 |
| 사후 Q&A | 결과물·로그로 즉석 출제. **문항당 3분, AI 없이** 답함. 설명이 구현과 맞는지 대조함 |

## 평가 관점 (각 100점)

| 축 | 보는 것 |
|---|---|
| **기술**(결과물) | 실제 동작, 직접 실행해 검증, 유지보수 가능한 구조, 보안·민감정보, 요구사항 충족 |
| **의도**(과정) | 목표·제약 정의, 작업 분해·위임, 진행 중 방향 조정, 검증 루프, 토큰 효율. 변별력이 가장 큼 |
| **인지**(이해도) | 설계 선택 이유, 동작 원리, 한계·실패 조건 예측. 코파톤 참가자 전원이 가장 낮았던 축 |

상위권 패턴: 코딩 실력보다 **문제 정의 → 서면 합의 → 판정·계산은 고정 코드, AI는 해석·초안 → 교차 검증 → 문서화**.
잘하는 지원자일수록 토큰을 적게 썼고, 개발 경험이 없는 참가자도 상위권에 올랐습니다.

## 데모 시험 사용법

> `exam/scenarios/*/hidden/`은 실무자 설정·채점표·정답입니다. **응시 전에 열지 마세요.**

Git Bash에서 실행합니다(Node, Claude Code 필요).

```bash
bash exam/probe.sh start        # 저장소 밖 ~/probe-runs/에 응시 폴더 생성, 마감 시각 표시 (기본 200분, 예: start 120)
bash exam/probe.sh agent        # 실무자 채팅 (VS Code 터미널을 분할해서 실행)
bash exam/probe.sh qa           # 마감 후: 기록 수집 + 사후 질문 5개 → answers.md에 AI 없이 답하기
bash exam/probe.sh grade        # 3축 채점 리포트 (probe/report.md)
SCENARIO=<폴더 이름> bash exam/probe.sh   # 이번만 다른 시나리오로 응시 (exam/scenarios/ 아래)
```

- 시나리오는 저장소 루트 `.env`의 `SCENARIO=`로 고릅니다(`.env.example` 참고). 비우면 `alarm-triage`, 명령줄 `SCENARIO=`가 우선
- 한 화면에서 연습합니다: VS Code 하나에 에디터, 왼쪽 터미널(응시자 `claude`), 오른쪽 터미널(`agent`)
- 응시자 AI 대화, 실무자 대화, 토큰 사용량은 Claude Code 기록에서 `exam/logs.mjs`가 뽑습니다(`node exam/logs.mjs --self-test`)
- 응시 폴더가 저장소 밖에 있어서 응시자 AI는 hidden 파일을 볼 수 없고, 실무자는 도구가 막혀 파일을 볼 수 없습니다

## 응시 요령

1. 처음 15분은 만들지 말고 실무자에게 묻는다: 최근 구체적 사례 → 지금 어떻게 버티는지 → 숫자(현재값·목표·어디서 재는지) → 누가 쓰고 누가 결정하는지 → 하지 말아야 할 것
2. 해법 단어(자동화, AI)는 문제를 다 들은 뒤에 꺼낸다. 모호하게 물으면 모호한 답이 온다
3. 합의한 문제·성공 기준·만들 것과 안 만들 것을 `docs/PRD.md`에 적고 실무자에게 확인받는다
4. `AGENTS.md`에 판단 원칙을 적는다: 판정·계산은 고정 코드, AI는 해석·초안, 사람이 결정할 지점은 사람에게
5. 작업은 작게 나눠 AI에게 맡기고, 단계마다 직접 실행해서 확인한다(실행 기록도 채점 증거)
6. 의미 있는 단위로 자주 커밋한다. 커밋 메시지도 과정 증거다
7. `uploads/`의 개인정보·비밀값이 코드·커밋·화면에 나오지 않게 한다
8. 결정과 그 이유는 `docs/DECISIONS.md`에 남긴다. 사후 Q&A의 재료이자 인수인계 문서다
9. AI가 만든 코드는 핵심 흐름을 직접 읽는다. 사후 Q&A는 AI 없이 "약점 → 위험의 파급 → 검증·개선 계획" 순서로 답한다
10. 마감 20분 전에 기능 추가를 멈추고 실행 확인, 문서, 커밋으로 마무리한다
