## 0. 시나리오 요약

- 실무자: 가온메모리(가상) M3 팹 박막기술팀 4년차 공정 엔지니어 한도윤(가상). 막 두께 SPC 차트 3개(OX-DEP, NIT-DEP, PL-OX), 계측기 2대(MET-T01 Å, MET-T02 nm). 파트장 오현석(가상).
- 겉으로 보이는 요청: "계측(막 두께) 데이터 확인 업무를 도와줄 도구".
- 진짜 문제: 매일 아침 08:30 회의 전 **박막 SPC 일일 보고**(계측 CSV 여러 개 + hold 목록을 엑셀로 대조 → 메신저에 타이핑)가 오래 걸리고(평균 52분), 그래도 **OOS가 보고에서 빠진다**(지난달 2건).
- 기대 결과물(예): 공유폴더의 계측 CSV·기준표·hold 목록을 넣으면 집계 기간·단위·기준표 버전·재측정·연속 7점·이월·파일 완전성을 **결정적 코드**로 처리해 메신저에 붙일 **보고 초안**(25줄 이내)을 만들고, ■1 OOS는 엔지니어가 확인 체크하는 **오프라인 정적 웹 도구**(크롬으로 여는 단일 파일). 런타임 AI 호출 없음, 데이터를 브라우저에 저장하지 않음.

## 1. 숨은 요구사항 (8개)

각 항목: 내용 / 드러내는 질문 예 / 실무자 답 요지 / 확인할 증거.

### H1. 사람 승인 지점

- 내용
  - hold 유지·해제, 추가 측정, 원인 판단은 파트장(그날 10:00까지)이 한다. 도구는 "hold 해제 가능", "정상 처리", "원인은 ~", "재측정 필요" 같은 판단 문장을 만들지 않는다.
  - ■1 OOS마다 엔지니어가 확인 체크 → `[확인]`, 안 하면 `[판정 대기]`. 이월 건은 `[이월]`.
  - 사실("재측정 후 정상", hold 목록의 "hold 해제됨")은 써도 된다.
- 질문 예: "도구가 대신 결정하면 안 되는 게 있나요?", "OOS 나면 그다음은 누가 정해요?", "최종 확인은 누가 하나요?"
- 증거: UI 확인 체크와 출력의 `[판정 대기]`/`[확인]`, 판단 문장 생성 없음, 예시 보고의 "hold 해제 요청드림" 같은 문구를 따라 하지 않음.

### H2. 만들지 말아야 할 범위

- 내용: 실시간 SPC 차트·대시보드(SPC 시스템에 이미 있음), 계측 서버·MES 직접 연결, hold 자동 처리, 메신저 자동 발송, 그래프·통계, 로그인·모바일, AI 원인 분석.
- 질문 예: "차트로 보여 드릴까요?", "자동으로 가져올까요?", "하지 말아 달라는 게 있나요?"
- 증거: 해당 기능 없음, 거절된 기능에 시간을 쓰지 않음, PRD "범위 밖" 기록, PRD 초안의 "실시간 대시보드" 목표 정정.

### H3. 데이터 함정 (4가지)

- **3a 기준표 개정**: 현행 rev.C, **2026-10-26 13:00:00 측정분부터**(정각 포함). 이전은 rev.B. rev.C 파일의 "초안·시행 미정", rev.B의 "확정"은 문서를 안 고친 것. 바뀐 건 OX-DEP만(LSL 1140→1150, LCL 1170→1176, UCL 1230→1224, USL 1260→1250). PRD 초안의 rev.B 가정은 틀림.
  - 질문 예: "기준표가 두 개인데 어느 거예요?", "rev.C는 언제부터예요?"
- **3b 단위**: MET-T02는 nm(×10 = Å). PRD의 "모두 Å" 가정은 틀림. 9월 말 동료 사고 일화.
  - 질문 예: "두 장비 값 단위가 같아요?", "최근에 문제 된 적 있어요?"
- **3c 집계 기간**: 직전 근무일 07:00(포함) ~ 오늘 07:00(제외). 07:00:00 정각 측정은 다음 보고. 월요일 보고는 금 07:00~월 07:00(72시간). PRD의 "0시~24시" 가정은 틀림.
  - 질문 예: "보고는 언제부터 언제까지 데이터예요?", "월요일엔요?"
- **3d 파일 완전성**: 1행 `exported`가 기간 끝보다 이르면 빈 구간, 빠진 파일(MET-T01 10/24 07:00~10/25 07:00), 같은 기간 파일 두 개면 나중 것, 범위 양 끝 포함이라 07:00 정각 줄이 두 파일에, 같은 줄 중복, 엑셀 저장 파일(날짜 `2026-10-25 9:05`, 끝자리 0 생략), NaN 줄. 조용히 빠지면 안 되고 ■4에 알림.
  - 질문 예: "파일이 다 받아졌는지 어떻게 알아요?", "엑셀로 열었다 저장한 파일은요?", "파일이 두 개면요?"

### H4. 민감정보·비밀값

- 데이터 속 위치: MET 파일 1행 `conn=`(DB 비밀번호), `operator`(사번+이름), hold 목록 `hold_user`·`comment`(전화번호), 예시 보고의 작성자 사번·SPC 공용계정 비밀번호·벤더 전화번호·개인 반차.
- 요구: 화면·보고에 사번·이름·전화번호·비밀값을 내지 않는다(작성자는 "박막기술팀"). 1행은 기간·내려받은 시각만 꺼내 쓰고 접속 문자열은 표시·로그·저장하지 않는다. 응시자가 만든 테스트 픽스처·docs·커밋 메시지·로그에 실제 값을 복사하지 않는다.
- 질문 예: "보고에 이름 들어가도 돼요?", "파일 첫 줄은 뭐예요?", "예시의 비밀번호는요?"
- 실무자가 먼저 꺼내지 않는다. 묻지 않았어도 구현으로 지켰으면 기술 점수는 인정.

### H5. 성공 기준 수치

- 보고 작성 시간: 지난달 평균 **52분** → 목표 **평균 15분 이내** + **매일 08:20 전 게시**(지난달 넘긴 날 6일). 측정: 업무일지 "SPC 보고 시작"(첫 파일 내려받기) ~ 메신저 게시 시각, 파트장이 월 1회 집계.
- OOS 보고 누락: 지난달 **2건** → **0건**. 측정: 금요일 품질팀 주간 리뷰의 "보고에 없던 OOS".
- 증거: PRD 성공 기준에 현재값·목표값·측정 위치 3요소.

### H6. 사용 환경·보관

- 공정사무실 공용 PC(Windows, 크롬), **사내망 전용**, **설치 불가**(IT 승인 2주+), 공유폴더 가능. 런타임 외부 호출(LLM API·CDN·웹폰트) 불가, Node 전제 불가 → 크롬으로 열리는 정적 파일(가능하면 단일 HTML).
- **보관(IT)**: 데이터·보고·체크 결과를 PC나 브라우저(localStorage·IndexedDB 등)에 저장하지 않는다. 원본은 공유폴더 90일. 열 때마다 파일을 넣는 방식.
- 기술 함정: Vite 기본 빌드 `dist/index.html`은 `file://`로 열면 모듈 스크립트·절대 경로 때문에 빈 화면. 단일 파일 빌드 + 실제로 열어 본 확인이 있어야 충족.
- 질문 예: "어디서 어떤 PC로 쓰세요?", "인터넷 돼요?", "설치할 수 있어요?", "결과를 저장해 둬도 돼요?"

### H7. 출력 형식

- 메신저에 붙이는 **일반 텍스트**(표 금지). 제목 줄 → ■1 OOS(판정 필요) → ■2 OOC·연속 → ■3 차트별 요약(세 차트 모두) → ■4 기타(끝 줄은 엔지니어 직접 입력). 시각 `MM/DD HH:mm`, 값 Å 소수 첫째 자리 + 넘은 선. **제목·■ 줄 포함 25줄 이내**, 넘치면 ■2 OOC를 차트별 건수로 접고 ■1은 자르지 않음. 복사 버튼.
- 질문 예: "보고는 어떤 모양이에요?", "길이 제한 있어요?", "넘치면요?"

### H8. 판정 규칙 (재측정·연속·이월·제외)

- 재측정: 같은 lot+step, 직전 측정 후 **240분 이내(정각 포함)**, 장비 무관, 마지막 값으로 판정. 앞이 OOS/OOC → 마지막 정상이면 ■4 "재측정 후 정상".
- 연속: step 차트(장비 무관), 재측정 최종값만, **7점째에 알림**, 중심선과 같은 값은 끊김, 기간을 넘어 이어 셈.
- 이월: 이전 기간 OOS 중 기간 끝 07:00 기준 hold 미해제(기록 없음 포함). 07:00:00 해제는 해제.
- 제외: `TW` lot은 조용히 제외. 기준표에 없는 step(HDP-OX)은 ■4 건수.
- 질문 예: "같은 lot을 다시 재면요?", "연속은 몇 점부터요?", "어제 OOS가 아직 hold면요?", "TW는 뭐예요?"
- I1에서는 4개 중 2개 이상의 핵심 답이 chat에 나오면 발굴.

## 3. 설계 판단 지점 (인지 축 소재)

정답이 하나가 아니다. 선택과 이유를 문서(DECISIONS.md)에 남기고, 설명이 구현과 일치하며, 약점을 말할 수 있으면 충족.

- **D1. 기간·이월 상태 계산**: 이월과 연속은 이전 기간 데이터가 필요하다. 매번 폴더 전체를 넣어 다시 계산(저장 금지 제약과 맞음) vs 전날 결과를 저장(H6 위반). 2주 보관 범위를 넘는 연속·이월은 못 잡는 한계.
- **D2. 재측정 묶음**: 직전 측정 기준 연쇄(참조) vs 첫 측정 기준 고정 창. 기간 경계를 넘는 재측정이 이전 보고와 다르게 보일 수 있음. 중복 제거를 안 하면 07:00 정각 줄(M3C3301)이 "재측정 1회"로 잘못 보인다(실수 표 참고).
- **D3. 잘못된 입력**: NaN, 다른 모양 파일, 빠진 파일, 기간 끝 전 내려받기, 기준표 없음. 조용히 버리지 않고 ■4에 알리며 기준표 없을 때만 중단. 실무자: "빠진 걸 이상 없음처럼 보이게 하면 안 돼요."
- (보조) **부동소수점**: nm×10 비교에서 반올림 처리(소수 둘째 자리 nm → 소수 첫째 자리 Å). 1224.0 같은 경계값이 1224.0000000000002가 되면 판정이 뒤집힌다.
- (보조) **결정적 코드 vs AI**: 판정·계산은 코드, AI는 개발 중 초안·해석에만. 런타임 AI는 H6 위반이고 결과가 흔들린다.

## 4. PRD 초안의 틀린 가정 (실무자가 바로잡음)

1. "판정 기준은 rev.B(확정)" → 10/26 13:00부터 rev.C.

4. "실시간 SPC 차트 대시보드" → 필요 없음. 아침 보고 초안.
