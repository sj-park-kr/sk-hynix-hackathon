# 프롬프트 템플릿

시험 중 바로 복사해 쓰는 템플릿입니다. `{…}`만 채우고, 문항·지문은 **요약하지 말고 원문 그대로** 붙여 넣습니다. AI는 질문마다 이전 대화를 기억하지 못한다고 가정합니다.

## 1. 문항형(객관식·주관식) — 풀이

연습실의 간식 문제·FAI 문제 모두 이 템플릿으로 정답(4/4)을 확인했습니다.

```
#역할
너는 {도메인} 데이터 분석가다.
#자료
첨부: {파일명(용도)}. 이미지 표는 모든 행을 텍스트로 옮긴 뒤 쓴다. 같은 값이 파일마다 다르면 어느 값을 왜 쓰는지 밝힌다.
#규칙
{지문의 조건·정의·주의사항 원문}
#문항
{문항 원문 + 보기 전부}
#작업
1) 문항별로 쓸 자료·규칙 조항을 먼저 적는다
2) 대상(사람·팀·항목·선택지)을 빠짐없이 표로 나열하고 조건을 하나씩 판정한다
3) 계산은 산식 → 대입 → 검산(합계·건수 일치)
4) 함정 점검: 비슷한 이름, 명단 밖 대상, 기준 시점, 지문 정의와 상식의 차이
5) 해석이 갈리면 각 해석의 답을 모두 구하고, 문항 문구(가정·정의)를 최우선 근거로 하나를 고른다
#출력
문항|답(보기 번호/값)|근거(파일, 행·쪽)|산식
```

## 2. 문항형 — 검증 (풀이와 다른 회차에서)

```
#역할
너는 독립 검증자다. 아래 답은 다른 사람이 냈으니 믿지 말고 원자료로 처음부터 다시 풀어라.
#자료
첨부: {파일명(용도)}
#규칙
{지문 원문}
#문항
{문항 원문 + 보기}
#검증대상
{1회차 답: 1-④ 2-T-06 …}
#작업
1) 문항마다 핵심 가정·정의 문구를 인용하고, 검증대상의 해석이 그 문구와 맞는지 판정
2) 1회차와 다른 방법으로 푼다(대상별 중간표를 먼저 만든 뒤 재계산)
#출력
문항|검증대상|재계산|일치|근거. 불일치는 원인 1줄.
```

두 결과가 다르면 3회차에 불일치 문항만 양쪽 근거를 붙여 다시 묻습니다.

## 3. 보고서형(서술형) — 계획 세우기

1회차에 단계별 계획과 단계별 프롬프트를 만들게 합니다. 채운 길이가 1,000자를 넘으면 섹션 제목을 줄여 씁니다.

```
#역할
너는 {도메인} 전문가이자 AI 작업 설계자다.
#문제점
{과제 상황 2~3줄: 현재값·목표값·격차, 핵심 쟁점}
#목표
{산출물} 완성용 단계별 계획과 단계별 프롬프트 작성.
필수 섹션: {섹션 목록}
#자료
첨부 {파일 범위}. 구성 파악용, 분석·실제 수치 인용 금지.
#제약사항
1. 계획만 세운다(계산·원인 판단 금지). 검증 포함 7단계 이하, 마지막은 검증. AI는 계획 포함 {N}회 이내, 남는 회차는 수정용.
2. 단계마다 새 세션(기억 없음, 원본 첨부만). 프롬프트는 역할·첨부·담당 요구사항 원문·작업·제약·출력을 담은 자립형. 분석 단계는 담당 섹션 완성 문안+인계 메모 출력.
3. 프롬프트 본문+인계 메모 1000자 이하, 인계 메모 500자 이하.
4. 인계 메모는 누적 원장(결론·수치+출처 한 줄씩), 마지막 메모가 검증 입력. 단계별 필요 사실은 첨부나 메모로 반드시 공급.
5. 첨부는 단계별 최소(행·쪽 지정). 값 1~2개만 필요하면 출처와 함께 프롬프트에 적는다.
6. 모든 수치·주장에 출처. 예) 13%(p.12, OOO.pdf)
7. 이해관계자 주장은 가설로 두고 데이터로 채택·기각, 지시·결정은 최신본 적용, 산식 공개·자체 검산.
8. 비식별은 유의사항이 요구할 때만 적용. 문제가 지목한 대상명은 그대로 쓴다.
9. 검증 단계는 원장을 원자료로 재계산·출처 대조해 오류와 수정안 제시.
#출력 형식
1) 단계표: 단계|담당 섹션|첨부(행·쪽)|메모 입력→출력
2) 단계별 프롬프트 전문(코드블록, 본문 글자 수)
```
